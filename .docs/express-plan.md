# Экспресс-план реализации MVP

## Цели MVP

Демонстрация базовой структуры сайта бренда и проверка визуальной концепции MVP.

MVP должен включать:
- Главную страницу, открывающуюся при первом переходе на сайт.
- Видео-блок на главной в формате слайд-шоу.
- Блок каталога под видео-блоком на главной (без полноценных карточек товаров на этом этапе).
- Отдельные страницы: главная, каталог, визуальное исследование.
- Рабочую навигацию между страницами.
- Визуальное направление, соответствующее философии бренда: метаморфозность и тишина.

---

## Шаги реализации
1. Уточнение границ MVP и сервисов
   - Зафиксировать минимальный набор микросервисов для MVP: `web`, `api-gateway` (или BFF), `catalog-service`, `media-service`.
   - Определить контракты между сервисами (REST JSON, версии эндпоинтов, формат ошибок).
   - Артефакт шага: `.docs/mvp-service-boundaries.md`.

2. Проектирование архитектуры и структуры репозитория
   - Описать структуру директорий под микросервисы и общие пакеты (`shared types`, `ui`, `config`).
   - Определить ответственность каждого сервиса и правила межсервисного взаимодействия.
   - Артефакт шага: `.docs/mvp-repo-architecture.md`.

3. Docker-базис
   - Подготовить `Dockerfile` для каждого сервиса.
   - Собрать `docker-compose.yml` для локальной среды (сети, порты, env, volumes).
   - Добавить `docker-compose.override.yml` для dev-режима.
   - Артефакт шага: `.docs/mvp-docker-baseline.md`.

4. Инфраструктурные зависимости
   - Подключить БД и кэш через Docker Compose (если требуются в рамках MVP).
   - Подготовить стартовые миграции/инициализацию для каталогов и медиа-метаданных.
   - Артефакт шага: `.docs/mvp-infra-dependencies.md`.

5. Backend MVP (микросервисы)
   - Реализовать минимальные API:
     - `catalog-service`: получение секций и ленты каталога.
     - `media-service`: получение списка видео/постеров для hero и visual research.
   - Добавить базовую валидацию и единый формат ошибок.
   - Артефакт шага: `.docs/mvp-backend-api.md`.

6. API Gateway / BFF
   - Настроить единый вход для frontend.
   - Проксировать и агрегировать данные из сервисов для UI.
   - Артефакт шага: `.docs/mvp-api-gateway.md`.

7. Frontend MVP в `Next.js`
   - Реализовать страницы `/`, `/catalog`, `/visual-research`.
   - Реализовать hero-видео-слайд-шоу, ленту каталога и страницу визуального исследования.
   - Подключить frontend к `api-gateway` вместо прямой статики там, где сервисы уже готовы.
   - Артефакт шага: `.docs/mvp-frontend-nextjs.md`.

8. Интернационализация и UI-полировка
   - Подключить `next-intl` для `ru/en`.
   - Применить анимации `Framer Motion` и финализировать визуальную подачу под философию бренда.
   - Артефакт шага: `.docs/mvp-i18n-ui-polish.md`.

9. Локальный QA в контейнерах
   - Проверить полный сценарий через `docker compose up`: навигация, API-ответы, медиа, адаптивность.
   - Прогнать lint/type-check/build для frontend и сервисов.

10. Документация и релизная фиксация
   - Актуализировать документацию под микросервисную модель.
   - Делать атомарные commits по conventional commits.
   - Использовать только аннотированные теги; `CHANGELOGE.md` обновлять только при реальном релизном push.

- Медиа-материалы для видео-слайд-шоу и визуального исследования (временные заглушки или согласованный контент)
- Язык разработки: `TypeScript` (strict mode)
- UI-фреймворк: `React`
- Основной фреймворк проекта: `Next.js` (App Router)
- Маршрутизация страниц: встроенный роутинг `Next.js` (`/`, `/catalog`, `/visual-research`)
- Интернационализация (UI): `next-intl` для `ru/en`
- Стилизация: `Tailwind CSS` + CSS variables для дизайн-токенов
- Анимации: `Framer Motion` (переходы секций, появление блоков, анимации ленты)
- Видео и медиа: HTML5 video (`.mp4`/`.webm`), poster-превью, lazy loading
- Управление состоянием на этапе MVP: локальный state React (без глобального state manager)
- Данные на этапе MVP: статические данные/JSON-заглушки
- Пакетный менеджер: `pnpm`
- Git-практика: аннотированные теги `git tag -a`, фиксация релизных изменений в `.docs/CHANGELOGE.md`
- Архитектура проекта: микросервисная архитектура
- Контейнеризация и окружение: `Docker` + `Docker Compose`
- Backend/API на этапе MVP: реализуется в рамках микросервисной архитектуры с контейнеризацией через Docker

## Оценка времени и затрат
Оценка по этапам:
- Этап 1 (структура и маршрутизация): 0.5 дня
- Этап 2 (главная + видео-блок + лента каталога): 1 день
- Этап 3 (страница каталога): 0.5 дня
- Этап 4 (страница визуального исследования): 0.5–1 день
- Этап 5 (проверка и полировка MVP): 0.5 дня

Итоговая оценка MVP:
- Срок: 3–3.5 рабочих дня
- Команда: 1 frontend-разработчик
- Риски: задержка по контенту (видео/визуалы), доработки по визуальному тону после первого просмотра

Критерий готовности MVP:
- Доступны 3 страницы: главная, каталог, визуальное исследование.
- Главная открывается по умолчанию и содержит видео-слайд-шоу + секцию каталога ниже.
- Навигация между страницами работает стабильно.
- Визуальная подача соответствует описанной философии бренда.
